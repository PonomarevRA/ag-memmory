# Резервное копирование локальной AgMemory

## Расписание и расположение

На macOS отдельный пользовательский LaunchAgent `com.agmemory.daily-backup` запускает
установленный executable без GUI ежедневно в **03:00 по локальному времени**. При загрузке
задания/входе пользователя есть дополнительная попытка, чтобы получить копию после простоя.
macOS выполняет пропущенный календарный запуск после пробуждения; выключенный компьютер
не может создавать бэкапы. Одной локальной дате соответствует один успешный архив;
повторный запуск проверяет существующий ZIP и выполняет очистку, не заменяя его.

Рабочие данные: `~/Library/Application Support/AgMemory`.
Автоматические ZIP: **`~/Library/Application Support/AgMemory-Backups/automatic`**.
Каталог отделён от приложения `/Applications/AgMemory.app` и рабочей базы.
Имя: **`DDMMYYYY.agmemmory.zip`**, например `21102026.agmemmory.zip`.
Время расписания задаётся plist, а не часовым поясом сохранённой памяти.

Установить или обновить расписание:

```bash
python3 /Applications/AgMemory.app/Contents/Resources/macos-backups.py install
python3 /Applications/AgMemory.app/Contents/Resources/macos-backups.py status
```

Создать сегодняшнюю копию вручную:

```bash
/Applications/AgMemory.app/Contents/MacOS/AgMemory.Web --backup
```

Опции команды: `--data-dir /absolute/path` и `--backup-dir /separate/path`.
Поддерживается стандартный локальный store `memory-graph.lancedb` внутри data-dir.
Настройки Web с внешним StoragePath отклоняются, чтобы не заявлять о полной копии
неохваченной базы. Другие отдельно настроенные MCP-хранилища нужно резервировать отдельно.

## Хранение

После публикации и проверки нового ZIP автоматически остаются:

- две последние успешные суточные копии;
- первая успешная копия прошлой календарной недели (понедельник — начало недели);
- первая успешная копия текущей недели, нужная как точка прошлой недели после смены недели.

В обычном случае это до четырёх ZIP; совпадающие даты хранятся одним файлом. Если в понедельник
компьютер не работал, якорем становится первый успешный бэкап соответствующей недели.
Если прошлую неделю целиком пропустили, сохраняется последний более ранний recovery point.
При первой установке архив начала прошлой недели появиться задним числом не может.

Удаляются только распознанные автоматические ZIP с корректной датой, собственным манифестом
и проверенными хешами. Ручные/неизвестные имена, каталоги, ссылки, будущие даты и повреждённые
архивы автоматически не удаляются. Ошибка создания или проверки не запускает удаление
прежних копий. Каталоги резервирования обновлений и `recovery` не входят в эту retention-политику.

## Согласованность и проверка

Снимок создаётся под существующими межпроцессными lease канонической базы, аудита и knowledge.
Все участвующие клиенты должны использовать актуальную версию с этим lease-протоколом.
Копирование снимка временно задерживает обращения к базе; длительность зависит от объёма и диска.
Сжатие выполняется после освобождения базы. В ZIP входят каноническая память, knowledge,
ключ цитат, настройки и остальные файлы каталога данных; служебные lease-файлы не переносятся.

ZIP публикуется атомарным переименованием после полного чтения и проверки SHA-256 каждого
файла по манифесту. Корректность ZIP без проверки данных недостаточна. Restore проверяет
inventory, пути, отсутствие дубликатов и ссылок, размеры и SHA-256. Лимиты: 200000 файлов,
64 GiB распакованных данных, 32 MiB манифеста. ZIP и staging получают права владельца;
это сжатый архив с данными и ключами, без шифрования. Системные symlink-псевдонимы вроде
`/tmp` и `/var` нужно заменять каноническими `/private/tmp` и `/private/var`.

Полный SHA-256 защищает от повреждений, но не удостоверяет автора изменённого архива.
Настройки из импортированного ZIP следует использовать только из своего доверенного бэкапа.

## Восстановление

Для просмотра/проверки можно извлечь ZIP в **новый, несуществующий** каталог:

```bash
/Applications/AgMemory.app/Contents/MacOS/AgMemory.Web \
  --restore-backup "$HOME/Library/Application Support/AgMemory-Backups/automatic/21102026.agmemmory.zip" \
  --restore-to "$HOME/AgMemory-restored"
```

Для восстановления рабочей установки закройте AgMemory и отключите его MCP-сессии
в Codex, Cursor и других клиентах. Затем выполните:

```bash
python3 /Applications/AgMemory.app/Contents/Resources/macos-backups.py restore \
  "$HOME/Library/Application Support/AgMemory-Backups/automatic/21102026.agmemmory.zip"
```

Контроллер откажется заменять данные, пока обнаруживает Web/MCP-процессы. Он сначала
полностью проверит ZIP и извлечёт его во временный каталог, приостановит LaunchAgent,
затем повторно проверит отсутствие клиентов. Старые данные перемещаются в
`~/Library/Application Support/AgMemory-Backups/recovery/before-restore-...`.
Проверенный каталог занимает их место; ошибка переименования возвращает старый каталог.
Расписание включается обратно. Запустите AgMemory и переподключите MCP: старые native handles
и кэши нельзя использовать после замены каталога. Старые данные для отката retention не удаляет.
Глобальные конфигурации IDE, находящиеся вне data-dir, в этот ZIP не входят.
Для сохранения прежней identity knowledge-профилей активируйте восстановление по прежнему
пути базы: она привязана к пути, scope и сохранённому ключу. Извлечение в другой каталог
подходит для проверки файлов, но не переносит автоматически authority-профили на новый путь.

Состояние запуска и exit code доступны через `status`; журналы — `last-run.log` и
`last-error.log` рядом с автоматическими ZIP. При повреждённом сегодняшнем архиве команда
откажется его затирать: сохраните его отдельно для диагностики и повторите запуск.
