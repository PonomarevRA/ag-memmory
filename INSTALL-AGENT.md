# Install AgMemory with an agent / Установка AgMemory с агентом

## English

1. Identify the OS, CPU, and MCP client. Check for an existing AgMemory installation. Read its configured data and backup locations; do not infer them from the checkout. If upgrading, verify a backup and follow the [backup guide](docs/memory/backup-policy.md) before replacing the app. Do not reset or migrate an existing store as part of setup.
2. Use a matching asset from [GitHub Releases](https://github.com/PonomarevRA/ag-memmory/releases) if available. Otherwise use the [source quick start](README.en.md#quick-start). For source MCP, run `dotnet build src/AgMemory.McpServer/AgMemory.McpServer.csproj -c Release` and use `dotnet` with the absolute path of the resulting `bin/Release/net10.0/AgMemory.McpServer.dll` as its sole argument. In a macOS app bundle, use its `Contents/MacOS/mcp/AgMemory.McpServer` executable and no arguments.
3. Open **Connect** in the running app. Use the generated client configuration where available, or read `/agent-setup.md` on the actual local app URL. Add a separate MCP entry named `agmemory`. The client config needs an absolute command or a command on PATH, arguments, and the correct `AGMEMORY_STORAGE_PATH`, `AGMEMORY_ACTOR_ID`, `AGMEMORY_CLIENT_ID`, and `AGMEMORY_TENANT_ID`. For a fresh source Web store, the default tenant is `local-development`. For existing records, use their actual configured scope, including project/workspace if set. Keep the other MCP entries. If installing the skill, use the complete folder from **Connect** or [skills/agmemory](skills/agmemory/), and preserve local edits.
4. Reconnect the client, list tools, and call `memory_capabilities` (or `memory_status` if that is the advertised diagnostic on an older server). Verify the Web app opens and report the actual URL and MCP result. If testing a write, use a separate temporary store. Do not include secrets or the contents of the user's memory in the report.

## Русский

1. Определите ОС, процессор и MCP-клиент. Проверьте, установлен ли AgMemory, и выясните его фактические каталоги данных и копий. При обновлении перед заменой приложения проверьте резервную копию по [руководству](docs/memory/backup-policy.md). Не сбрасывайте и не мигрируйте существующую базу в рамках подключения.
2. Если есть подходящий файл в [GitHub Releases](https://github.com/PonomarevRA/ag-memmory/releases), используйте его. Иначе следуйте [быстрому запуску из исходников](README.md#быстрый-запуск). Для MCP из исходников выполните `dotnet build src/AgMemory.McpServer/AgMemory.McpServer.csproj -c Release`. Команда — `dotnet`, единственный аргумент — абсолютный путь к полученному `bin/Release/net10.0/AgMemory.McpServer.dll`. В приложении macOS укажите исполняемый файл `Contents/MacOS/mcp/AgMemory.McpServer` без аргументов.
3. Откройте **Подключить** в запущенном приложении. Используйте готовую конфигурацию клиента, если она доступна, или прочитайте `/agent-setup.md` по фактическому локальному адресу. Добавьте отдельную запись MCP с именем `agmemory`. Укажите команду с абсолютным путём или доступную через PATH, аргументы и нужные `AGMEMORY_STORAGE_PATH`, `AGMEMORY_ACTOR_ID`, `AGMEMORY_CLIENT_ID`, `AGMEMORY_TENANT_ID`. Для новой базы Web из исходников tenant по умолчанию — `local-development`. Для существующих записей используйте их область, включая project/workspace, если они заданы. Сохраните остальные MCP-серверы. Для навыка возьмите полную папку из раздела **Подключить** или [skills/agmemory](skills/agmemory/); сохраните локальные правки.
4. Переподключите клиент, получите список инструментов и вызовите `memory_capabilities` (или `memory_status`, если это диагностический инструмент старой версии). Проверьте открытие Web и сообщите фактический адрес и результат MCP. Тестовую запись выполняйте только в отдельной временной базе. Не включайте секреты и содержимое памяти пользователя в отчёт.
