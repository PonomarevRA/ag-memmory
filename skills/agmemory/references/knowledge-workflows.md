# Knowledge and reusable solutions

Use this reference only when `knowledge_capabilities` is exposed and reports the required operation. Legacy clients continue their existing workflow. Canonical records in the exact scope can be shared across actors. By default knowledge state remains actor-isolated. An operator can explicitly opt local teammates into one knowledge partition with `AGMEMORY_KNOWLEDGE_TEAM_ID` in each MCP server configuration and matching `MemoryGraph:KnowledgeTeamId` in the local Web configuration. This is a trusted local team, not authenticated per-agent access control. Never change this setting automatically; configuration changes require the user's authorization. Keep actor/client labels distinct for provenance.

Compare `KnowledgeSharing=local_team` and equal `KnowledgeProfileRef` from capabilities to establish shared procedures, L2, warm residency and feedback. `ProfileRef` still binds the actor and citation authority; equal counts are insufficient. Without the team setting, older actor partitions remain unchanged. Opting in selects a separate team document and does not automatically merge older actor knowledge. Keep their data and migrate only through an explicit reviewed task.

Retrieve your own procedure/citation/receipt references. Do not pass another agent's references as your own: the server continues to bind them to their issuer. Share safe query terms, a goal and applicability so the receiving agent can retrieve its own reference. Prefix task, occurrence, application and request keys with a stable agent/task label to avoid accidental collisions in shared state; preserve keys and payload on retries. Legacy L2 uses one shared CAS revision. When task_context/task_working_update are advertised, keep one stable taskKey and use that task partition instead; it never inherits legacy L2. Task labels still confer no private-agent identity. Read the matching partition before CAS. Knowledge tools retain the safe `SchemaVersion`, `Data`, `Error` envelope.

## Reuse a procedure

For a recurring operation, search once with `memory_procedures(query, environment, limit=3)`. Environment is an exact applicability label; goal and aliases support alternate wording, not semantic search. Check prerequisites and the current task's authorization before applying advice. Retrieval never authorizes execution.

When a reusable approach is new or materially improved, use `memory_procedure` with goal, aliases, applicability, preconditions, compact steps and verification criteria. Reference a reviewed relative runbook instead of saving multiline shell, logs, private hosts or credentials. New procedure: `procedureRef=null`, `expectedRevision=0`. Update with the opaque reference and revision; preserve exact semantic inputs and requestKey on retries. Prior revisions remain linked to historical applications.

`memory_application` takes the opaque procedureRef, applicationKey, environment, evidence, outcome and requestKey (optional occurrenceKey); do not pass a procedure revision or expectedRevision to this operation. It records one attempt: ReportedSuccess, Partial, Failed, NotApplicable or Unknown. State what was checked in sanitized evidence. VerifiedSuccess needs a trusted verifier and is unavailable. Ordinary successful operations do not create artificial incidents or duplicate an unchanged lesson. Downloading logs does not establish that a service outage is fixed.

For a meaningful new failure retain the Incident/LessonLearned workflow. `memory_occurrence` distinguishes an event key from a problem family key: a new real event needs a new event key; a delivery retry preserves its key and requestKey. Optional application occurrenceKey links an attempt without closing the event. `memory_occurrence_update` CAS-updates only reported status; it never establishes a verified root-cause repair.

## Working context and feedback

`working_update` saves a shared-authority L2 summary for up to 24 hours. Keep facts, assumptions and questions distinct. Read WorkingSetRevision from working_context for expectedRevision, even when WorkingSet is null after expiry; zero means no prior set. Never guess a hidden fence on an older server. The server does not authenticate individual subagents. Private L1 stays with the client.

`working_context(query,budget,mode)` returns L2 and current sources. Empty working queries resume only the bounded warm set. Every nonempty query uses the configured canonical ranking so weak warm hits cannot hide better answers. Working mode also includes unexpired L2 and labels current warm hits L3; search mode omits L2. Whole candidates that exceed the remaining budget are skipped. Current servers inspect up to 64 ranked candidates and return at most ten complete records; older servers may inspect only ten. There is no semantic or global coverage guarantee. Budget estimates serialized characters, not model tokens. Required L2 overflow fails explicitly: obtain an adequate budget or deliberately compact the summary.

The default ranking remains `lexical`. Operators may opt into BM25 through `AGMEMORY_RECALL_RANKING=bm25` in server configuration; inspect `memory_capabilities.RetrievalMode` rather than guessing support. BM25 uses whole tokens and exact eligible-scope statistics. New servers may use a derived exact-scope posting index with query-time lifecycle/type/expiry filters; cache bounds or I/O failure fall back to scans. AGMEMORY_RECALL_INDEX=off selects scans. Packaged RU/EN phrase aliases and case-sensitive acronyms such as AFTER are finite, versioned lexical expansions; ordinary after stays literal. They are not semantic search or a general paraphrase guarantee. AGMEMORY_QUERY_ALIASES=off disables expansion. Never change operator configuration automatically.

If the advertised `knowledge_capabilities` input schema supports `includeUsage`, request `includeUsage=true` only when diagnosing capacity. `Capacity` reports domain collection counts, headroom and an 80% warning; it excludes filesystem byte/profile limits. Reads consume no replay receipt. Existing receipts remain retained; do not delete them to make room or claim automatic compaction. Older servers without the parameter continue ordinary discovery without it.

`memory_metadata` classifies a current citation as Knowledge, Procedure, Experience or Unclassified, with its own expectedMetadataRevision independent of source revision. No arbitrary MCP payload approves L111 foundations.

`memory_present` registers exposure to a current citation and returns a purpose-bound receipt. `memory_feedback` CAS-updates agent signals for it. Applied is independent of usefulness; Helpful/Harmful, relevance and content issues have separate dimensions. taskKey is a caller label, not evidence of independent tasks or human identity. Do not fabricate usage, confidence or success. Explicit presentation can populate bounded pilot L3; residency does not promote truth.

`memory_review` returns suggestions. `memory_warm_exclude` explicitly excludes/restores classified sources only in warm residency. Canonical search can still find them; there is no automatic archival or hard deletion. Source correction/expiry invalidates old warm revisions and feedback eligibility; retrieve current sources.

## Failure boundaries

Keys are nonsecret ASCII letters/digits/underscores/hyphens, at most 100 characters. Keep the same key on uncertain retries; inspect conflict instead of using a new key to overwrite. capacity_exceeded requires authorized maintenance, not unbounded retries or silently dropping receipts. These writes never replace the single required final Outcome. Do not save a duplicate Procedure/LessonLearned for each unchanged use. Human ratings, trusted success verification, foundation approval and authenticated subagent identity are not inferred from labels.

## Optional task, evidence and transfer tools

Only use tools actually advertised by the current connection. task_context/task_working_update take one symbolic taskKey within existing authority. Read that task's WorkingSetRevision even after expiry; never reuse a different task's fence. The separate task namespace is bounded to128 profiles per store and retains the legacy receipt limit per partition. Canonical sources and warm residency remain shared within configured authority. Legacy working_context/working_update keep their original shared state and format.

memory_evidence rechecks a current citation. It returns LegacyUnknown for records without structured claims; no observation or effective date is inferred from content. Raw evidence HasConflict=null means conflict analysis was not performed. Use memory_claims for an explicit tuple/time question.

memory_claim appends a caller-reported subject/predicate/value with SourceKind UserStatement, ToolObservation or AgentInference; none is factual verification. Optional observedAtUtc is explicitly reported, not inferred from UpdatedAt. Validity is half-open [validFromUtc,validToUtc); both missing means unknown. Preserve a stable requestKey. A supersedesRef must refer to the same tuple and never rewrites the old record.

memory_claims separates asOfUtc (time the assertion describes) from knownAtUtc (when it was recorded). Different eligible values remain a conflict, including when result limit hides some cards. Current source revision is required by default. Explicit includeHistorical returns unavailable/stale sources flagged without fresh citations, while a scope move/deletion revokes projection. Missing dates stay unknown. Claims/evidence are separate from canonical type, confidence and authority.

memory_procedure_discovery accepts declared capabilities and optional environmentFamily. Exact labels without facets still require review. Missing required capabilities exclude a card; a family match in another environment only returns TransferCandidateNeedsReview. Check preconditions and command mapping under current authorization. memory_procedure_facets attaches immutable declarations to one exact procedure revision; change the procedure revision to change facets. Metadata qualification is not proof of execution or successful model transfer.

## Operator journal migration

Legacy knowledge remains the default. The installed MCP binary accepts operator-only --knowledge-migrate, --knowledge-status and --knowledge-rollback-before-writes commands using its ordinary configured environment. KnowledgeMaintenance in a source checkout is a convenience wrapper. The migration can move the configured shared profile to a transactional journal, retaining every replay receipt and exact v1 backup bytes. It fences older knowledge writers; reconnect them using AGMEMORY_KNOWLEDGE_STORAGE=journal. Do not run migration as an incidental agent tool action. Canonical memory APIs and the separate task namespace remain compatible.

The journal retains receipts without eviction, bounded by1,000,000 receipts across the namespace and a512MiB SQLite database. Capacity reports namespace request counts and a separate ProfileRequestCount. The byte limit covers the database, not rollback-journal files or preserved v1 backups. Task L2 remains the separately bounded schema-v1 store. Rollback-before-writes is permitted only before any accepted journal mutation; later rollback needs an explicit restore/export workflow. Process interruption tests do not prove power-loss durability. Backups coordinate the shared, task and annotation leases and include journal data.
